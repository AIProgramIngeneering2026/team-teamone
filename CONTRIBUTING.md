# Как работать над CampusSpot

CampusSpot — API для бронирования коворкингов и аудиторий кампуса.
Код и PR ведём в `team-teamone`, отчёты по практикам сдаём в `Zadania`.

## 1. Откройте проект

При первом подключении клонируйте репозиторий и откройте его папку.

```bash
git clone https://github.com/AIProgramIngeneering2026/team-teamone.git
cd team-teamone
```

Пока сервис в разработке, можно начать с документации.
Когда команды запуска и проверки появятся в [README](README.md),
используйте их локально и в CI.

## 2. Возьмите задачу

- Откройте [Issues](https://github.com/AIProgramIngeneering2026/team-teamone/issues).
- Для первого PR ищите `good first issue` или предложите небольшую правку документации.
- Запишите ожидаемый результат и назначьте исполнителя в **Assignees**.
- Меняете API, данные или правила бронирования? Согласуйте правку в issue.
- Архитектурное решение запишите в ADR. Укажите выбор, альтернативы и причину.
- Застряли? Опишите препятствие в issue и попросите помощи.
- За 48 часов до срока практики задачу без PR можно взять, сообщив об этом в issue.
  Обновите исполнителя. Задача засчитывается тому, кто её сделал.

## 3. Создайте ветку и коммит

Ответвитесь от свежей `main`. Формат ветки — `тип/номер-описание`.
Подставьте номер своей задачи вместо `12`.

```bash
git switch main
git pull --ff-only
git switch -c docs/12-classroom-conflict
```

Например, уточните в `README.md`, как расписание влияет на доступность аудитории.
Проверьте ссылки и примеры. Если правили код, запустите проверки из README.
Один коммит — одна проверяемая цель. Исправление и тест к нему добавляйте вместе.

```bash
git add README.md
git --no-pager diff --cached
git commit -m "docs(booking): уточнить проверку расписания"
git push -u origin HEAD
```

Формат коммита — `тип(область): действие`. Область можно опустить.
Крупную задачу разделите на PR. Для зависимых PR укажите ссылки и порядок слияния.

## 4. Откройте PR

- Откройте PR из своей ветки в `main`. Прямой push и force push в `main` запрещены.
- Укажите, что изменилось и зачем. Добавьте `Closes #12` для полной правки
  или `Refs #12` для части задачи.
- Если меняли общий контракт, опишите, кого затронет правка.
- Запишите шаги проверки и ожидаемый результат. Для ручной проверки укажите хеш коммита.
- Через **Reviewers** позовите коллегу. Меняете общий контракт? Позовите его потребителей.
- Согласуйте срок ревью. Если срок прошёл, напомните ревьюеру в PR.

## 5. Получите одобрение и влейте PR

**Ревьюер** проверяет критерии задачи и пограничные случаи.
Отмечает блокирующие замечания и отправляет ревью через **Submit review**.

**Автор** исправляет замечания и повторно запрашивает ревью после изменения PR.
Если в `main` появились связанные правки, проверяет результат объединения веток.

### Definition of Done

- [ ] Критерии задачи выполнены. Проверки прошли на итоговой версии PR.
- [ ] Изменения поведения покрыты тестами. Для бага есть тест, который ловит его.
- [ ] Затронутые контракты, миграции и документация обновлены.
- [ ] В тестах используются вымышленные данные. В изменениях отсутствуют секреты.
- [ ] Автор понимает весь внесённый код, включая сгенерированный ИИ.
- [ ] Коллега одобрил итоговую версию, блокирующие замечания закрыты.

С третьей практики, если внутри команды некому одобрить PR, зовите проверяющую команду.
Если GitHub не засчитывает её одобрение, обратитесь к владельцу репозитория или преподавателю.

## Что проверить в CampusSpot

- **Бронь.** Проверьте допустимые и запрещённые переходы `Job`.
  После отмены подтверждённой брони проверьте доступность интервала.
- **Правила.** Проверьте пересечения с парами и бронями, лимиты и доступ по роли.
- **Повторы.** Из двух одновременных заявок на один ресурс в пересекающиеся интервалы
  подтверждается одна, если обе по отдельности проходят проверки.
  Повтор запроса с тем же ключом идемпотентности оставляет одну заявку.
- **Интеграции.** На заглушке проверьте таймаут, лимит повторных попыток и сбои.

Сверяйте границы задач с README. Для LLM сейчас предусмотрена точка расширения.
Обработка запросов на естественном языке относится ко второму семестру.

## Сдайте практику

- Сохраните ссылки на влитые PR и содержательные ревью.
- От команды откройте один PR с `teams/teamone/pN.md` из своего форка `Zadania`.
- Укажите результат, вклад участников и препятствия. Срок — начало следующей практики.
- К сроку командный результат должен быть в `main`.
- Для [практики 1](https://github.com/AIProgramIngeneering2026/Zadania/blob/main/tasks/p1.md)
  заполните все разделы [шаблона заявки](https://github.com/AIProgramIngeneering2026/Zadania/blob/main/templates/p1.md).
  Если препятствий не было, напишите «нет».
- К началу практики 2 у каждого должны быть влитый PR и своё ревью.
  Для приёмки практики 2 заявка должна получить метку `full`.
